# 01 决策摘要与产品边界

### 1.1 项目定位

本项目是一个个人模型网关，不是聊天产品，也不是免费额度交易或分发平台。消费端负责自身业务、会话历史和工具执行；网关负责接入、协议适配、允许范围内的路由、故障处理与调用记录。

### 1.2 本次收敛后的决定

| 议题 | 建议基线 | 调整原因 |
| --- | --- | --- |
| 对外协议 | 先支持 Chat Completions 的明确子集 | 不把“接口兼容”误写为“所有能力等价” |
| 调度策略 | 人工优先级 + 硬性资格筛选 + 有限备用 | 不引入未经评测的质量评分公式 |
| 免费监控 | 可用性、限流反馈和有来源的额度观察 | 不承诺所有厂商都有精确余额接口 |
| 开源复用 | LiteLLM 为首选验证对象 | 文档能力必须再通过版本级测试 [S01][S02] |
| 自研范围 | 配置校验、必要的安全约束、缺失的诊断字段 | 不重写供应商适配和流式协议 |
| 管理方式 | 配置文件管理模型与路由；现成后台管理调用密钥和查日志 | 避免两套模型配置相互覆盖 [S03] |
| 技术栈 | 首版不强制引入 Spring Boot、Next.js、Redis | 学习目标与实际运行需求分开 |
| 可用性承诺 | 尽力服务；允许无免费模型可用 | 不为了成功率偷偷付费、越权或降低能力 |

### 1.3 不可突破的约束

每次实际尝试都必须满足免费资格、消费端权限、隐私范围和能力约束。没有符合条件的目标就停止。不能通过丢弃关键参数让请求“看起来成功”，不能在流已交付后拼接另一模型的回答，也不能将未知用量记作零。

免费只指本次推理不产生供应商 API 费用；服务器、电费、网络和维护时间不在“零费用”承诺中。项目不使用逆向网页接口，不自动注册或轮换账户规避限制，不绕过供应商安全限制。

### 1.4 什么才算首版成功

一个真实消费端使用固定接口完成文本任务；主渠道不可用时可控地切到合格备用；全部不可用时给出可诊断错误；能够查到实际尝试和失败原因；升级、撤销密钥与回滚配置均经过测试。完成这些后，才判断是否值得继续自研界面。

# 02 使用场景与版本范围

### 2.1 使用者与场景

| 使用者 / 场景 | 期望结果 | 网关不负责的部分 |
| --- | --- | --- |
| 脚本或应用调用 | 一个地址、一个受限密钥、一个逻辑模型别名 | 消费端业务逻辑、结果是否满足业务要求 |
| 个人管理员配置资源 | 明确哪些渠道可以接收哪些请求 | 替用户开通账户、同意条款或启用收费 |
| 排查失败或切换 | 通过请求 ID 找到尝试链与中断位置 | 推断无法获得的上游内部执行过程 |
| 未来工具型应用 | 只在兼容性验证后转发工具调用 | 自动执行工具、保证外部操作恰好一次 |

### 2.2 分版本交付

| 能力 | V0 技术验证 | V1 个人可用版 | V1.1 按需扩展 |
| --- | --- | --- | --- |
| 文本与流式输出 | 单渠道验证 | 两个独立渠道、稳定契约 | 扩大已验证模型池 |
| 逻辑模型 | 一个别名 | 默认 general-free；备用候选明确 | coding-free 等需评测后增加 |
| 免费与权限约束 | 验证可封闭所有调用路径 | 必须覆盖主调用和备用尝试 | 细分隐私配置与更多账户类型 |
| 额度监控 | 识别可取得的数据 | 限流反馈、冷却、已知 / 估算 / 未知 | 多窗口预测、共享池预扣与对账 |
| 管理界面 | 使用原生后台 | 优先复用；缺失项用日志与配置补齐 | 必要时开发只读控制台及发布流程 |
| 结构化输出、工具调用 | 仅做需求匹配实验 | 默认不公开承诺支持 | 单独能力配置、测试通过后开放 |
| 图片、语音、Responses 等 | 不作为启动前提 | 不支持的请求明确拒绝 | 有真实消费端需求才扩展 |

### 2.3 V1 明确不做

不做多租户注册、充值套餐、对外售卖、高可用集群、Kubernetes、自动发现并启用免费模型、语义缓存、RAG、Agent 执行器、模型自动裁判、会话长期记忆和流中断续写。没有精确额度数据时，不爬取私人控制台来制造实时余额。

### 2.4 真实消费端是协议选择门槛

目前尚未指定第一消费端。V0 必须确认它实际调用的协议、消息角色、默认参数、流式结束判断和重试行为。仅支持 Responses 或要求工具调用的客户端，不能因为能填写 API 地址就被列为 V1 兼容；应先扩展能力或更换首个验证客户端。

| FR-11 | L | 结构化输出与工具调用分能力开放；任何候选不支持时不得静默降级 | 扩展验收 |

### 实现约束

LiteLLM 可以拒绝不支持的参数，也可以配置为丢弃参数；V1 选择前者，并阻止消费端覆盖这一规则。[S04] 不能把一条“drop_params 关闭”的配置当作充分证明，必须对主目标与备用目标分别构造不支持参数的测试。

公共协议不追加自定义正文包装层，不要求消费端识别网关专属 SSE 事件。调用追踪与资源状态优先放到响应头、内部日志和管理界面。

### 范围解释

“统一接口”统一的是调用契约，不是推理质量、输出内容或确定性。“模型别名”表示一组经过批准的候选，不承诺候选回答完全一致。公司源码和敏感个人信息默认不进入未经审查的免费渠道。

| 编号 | 级别 | 需求及边界 | 验收 |
| --- | --- | --- | --- |
| FR-12 | M | 按人工优先级选目标；高优先级不可用才降到下一候选；先过滤再排序 | AT-03、11 |

| FR-16 | M | 重启不把额度视为全新；无法恢复的状态降为未知；异常期间不密集健康探测 | AT-14 |

| FR-20 | M | 固定依赖版本；升级前运行契约与故障测试；备份配置及必要数据库 | AT-20、21 |
| FR-21 | M | 管理入口和消费入口隔离；只放行需要的端点和上游目标 | AT-16、17 |
| FR-22 | S | 复用后台展示资源状态、调用记录和密钥；读不到的指标不制造展示值 | AT-09、18 |
| FR-23 | L | 增加跨实例共享计数、原子预扣、自动对账与路由编辑工作流 | 扩展验收 |

### 实现强度不等于界面完整度

M 级要求是行为底线，不意味着必须创建一个新页面或一张新表。配置、已有后台、结构化日志或很小的插件都可以满足需求。若关键约束无法用选定版本实现，应减少能力范围或暂停启用该渠道，而不是用界面提示替代后端约束。

### 首版监控的准确性边界

V1 是“反馈驱动的可用性调度”，不是供应商账单系统。没有权威数据时允许显示未知，也允许在已确认不会产生付费的渠道上进行受控尝试；未知免费资格、未知数据使用权限则不允许调用。

# 05 技术架构与开源复用

### 5.1 运行链路

消费端通过受限密钥访问网关。网关完成输入与权限检查，按批准的路由选择实际渠道，调用供应商并转换响应，最后记录尝试结果。反向代理或私有网络入口负责暴露范围、TLS 和基本请求限制；不增加第二套路由器。

管理操作走独立的私有入口。模型与路由通过受版本管理的配置发布；消费端密钥与原生运行记录由网关及其数据库管理。

| 组件 | V1 角色 | 采用方式 |
| --- | --- | --- |
| LiteLLM | 供应商适配、兼容 API、流式转发、原生路由与冷却 | 固定经过测试的发行版本；独立部署，不 fork [S01][S02] |
| PostgreSQL | 原生受限密钥、管理后台及所选功能需要的数据 | 使用网关支持的版本；不以 SQLite 替换 [S05][S06] |
| Docker Compose | 单机服务编排与可重复启动 | 固定镜像、挂载受控配置和数据卷 |
| 现有入口组件 | 私有访问、端点隔离和 TLS | 优先沿用已有设施；没有时再选择一种反向代理 |
| 小型扩展 | 仅补白名单校验、缺失的状态或脱敏诊断 | 使用官方扩展点；所有备用尝试的覆盖范围待实测 [S07] |
| 测试工具 | 模拟限流、断流、超时和额度重置 | 独立模拟上游，避免反复消耗真实免费额度 |

### 5.2 暂缓的组件

Spring Boot 不作为每次推理必须经过的服务，也不先建实时控制面。Next.js 自研控制台只有在原生界面确实不足时才启动；默认先做只读诊断，不再建聊天平台。Redis 不是默认依赖：只有选用功能需要它，或出现多进程、跨实例共享状态时再引入，不能以“只有一个人用”为理由忽略进程间计数问题。

### 5.3 扩展的审批标准

先写出可复现的功能缺口，再确认原生配置或管理功能不能解决，最后才添加扩展。扩展不得重写供应商 SDK、SSE 解析器或整套路由引擎。普通入口钩子不自动等于“每次备用尝试前执行”；无法验证覆盖全部尝试时，不启用依赖该钩子的敏感路由。

### 5.4 开源许可与可靠性

LiteLLM 仓库的非 enterprise 部分按其 LICENSE 采用 MIT；企业目录有独立许可。[S10] 这是候选依据，不是稳定性保证。记录实际使用模块、版本和许可证，核对安全公告后再通过验收。[S09]

# 06 技术验证门槛与配置权威

### 6.1 V0 必须回答的问题

| 门槛 | 验证内容 | 不通过时的处理 |
| --- | --- | --- |
| G-01 | 首个真实消费端能使用选定端点、角色和参数子集 | 调整契约或消费端，不宣传兼容 |
| G-02 | 主调用和备用路径都不能越过免费、模型授权与参数限制 | 封闭候选范围或添加可测试薄扩展；仍不通过则停用 |
| G-03 | 流已向消费端交付后，不发生透明换模型；中断能被识别 | 不开放该流式组合，不能以成功终止掩盖 |
| G-04 | 最大尝试次数、时限、取消与冷却按预期执行 | 修正配置；必要时减少为单候选验证 |
| G-05 | 能关联全部尝试，且日志不泄露正文或密钥 | 补最小诊断扩展；未达成前不接真实敏感数据 |
| G-06 | 所需功能属于可用开源范围，版本已核对安全公告 | 换用可用功能或重新评估网关候选 |

### 6.2 唯一权威源：配置文件模式

V1 选择文件模式管理模型、路由和安全策略，所有变更归入一个配置版本。原生数据库保存密钥及运行数据，不作为第二个模型配置入口。原生界面中的模型新增、路由编辑和同名设置写入不纳入 V1 工作流。

LiteLLM 文档区分文件管理与数据库管理；数据库中部分设置会覆盖文件中的同名设置。[S03] 因此上线前必须检查并清理相互冲突的覆盖项。后台不能呈现“保存成功但实际未生效”的假象；无法限制编辑入口时，隐藏相应入口或只开放必要管理路径。

### 6.3 配置发布流程

配置变更先验证别名、候选资格、权限、能力交集和密钥引用，再执行模拟故障测试。发布时记录版本摘要，先停止接收新请求并等待存量请求结束，再切换配置并健康检查。超出等待时限的请求按中断处理，不转成成功。

V1 接受维护窗口，不要求无缝热更新。检查失败则回到上一份配置；涉及数据库迁移时，按该版本兼容性和备份恢复方案处理，不假设旧镜像能读取新数据库。

### 6.4 本稿尚未确定的版本

不写死“最新版本就是安全版本”。T-02 开发任务必须产出镜像版本或摘要、依赖清单、许可证清单、公告核查日期和验证报告；只有这些信息齐备后，技术栈才从“候选”变为“已验证基线”。

# 07 对外契约：输入与能力范围

### 7.1 消费端入口

| 接口 | V1 行为 |

### 7.2 输入字段基线

| 字段 | 规则 |
| --- | --- |
| model | 必填；V1 默认 general-free；不接受任意真实模型名来绕过授权 |
| messages | 必填有序数组；初始仅 system、user、assistant 和纯文本内容；其他角色单独验证后开放 |
| stream | 布尔值；默认 false |
| max_completion_tokens | 可选正整数；建议默认 1024、上限 4096；实际限制还须符合目标上下文和输出上限 |
| max_tokens | 兼容入口；仅在选定客户端确有需要且映射测试通过后接受；与上一字段同时出现则拒绝 |
| temperature 等采样参数 | 非基础保证项；仅在能力矩阵明确支持时允许，不能静默删除 |
| stream_options.include_usage | 通过兼容性测试后开放；用量缺失不影响识别流中断，但不得填造实测值 |
| n | 默认 1；不支持多候选生成 |
| tools、response_format、图片 / 音频字段 | V1 默认拒绝；后续按独立能力配置扩展 |
| api_base、api_key、fallbacks、user_config 等路由覆盖字段 | 消费入口一律拒绝；也不接受绕过校验的参数开关 |

### 7.3 能力矩阵与会话责任

每条部署记录实际验证过的输入角色、文本 / 流式支持、输出长度限制和关键参数。general-free 的契约取批准候选的能力交集，不由模型宣传名称推断。

消费端传入完整必要历史；网关不保留跨请求会话状态，不自动摘要或裁剪。上下文过长时应明确失败，不把不同 Token 估算器得到的数值当作精确边界。换模型前保留原请求的业务约束和消息顺序。

# 08 对外契约：响应、流式与错误

### 8.1 响应约定

| 项目 | 约定 |
| --- | --- |
| 正常响应 | 沿用所选 Chat Completions 响应形状，不额外包装 data/result |
| id 与追踪 | 返回稳定响应 ID；建议响应头 X-Request-ID 作为诊断标识，具体适配在 V0 冻结 |
| model | 允许返回实际模型标识；不要求与请求别名相同；逻辑别名与部署信息另记日志 |
| choices | V1 单结果；保留结束原因，区分自然结束、长度截断、内容限制等 |
| usage | 上游未提供则允许为空或缺失；可区分来源的估算放诊断数据，不冒充实测 |
| 管理诊断 | 保存候选排除原因、尝试链和配置版本；公共错误不暴露密钥或上游内部地址 |

### 8.2 流式规则

对外使用兼容的 SSE 数据格式，不新增自定义事件协议。只要已经转发任何上游 SSE 事件，即使只是角色信息，也禁止透明切换；V1 不做跨模型拼接或续写。正常结束按所选协议发送结束信息；中断必须保留“未完成”语义，不能伪造正常结束。

HTTP 头已经发出后，不能再依赖更改状态码表达错误。应使用经过客户端验证的错误块并关闭流；客户端不支持错误块时，关闭流且缺失正常完成标志，并在日志标记失败。此行为必须通过 G-03。流中断可能缺少最终用量块，官方流式选项也明确提示这一点。[S15]

### 8.3 非流式错误映射目标

| 场景 | HTTP / 稳定错误码 | 行为 |
| --- | --- | --- |
| 格式或能力不支持 | 400 / invalid_request 或 unsupported_capability | 不调用上游，不备用 |
| 消费密钥无效 / 无权 | 401 或 403 / authentication_error 或 access_denied | 不调用上游 |
| 无此逻辑别名 | 404 / model_not_found | 不静默改为默认模型 |
| 本地并发 / 已知限流 | 429 / rate_limited | 已知等待信息时返回 Retry-After |
| 无符合条件的可用渠道 | 503 / no_eligible_free_model | 不自动收费、不编造恢复时刻 |
| 上游异常 / 上游凭据异常 | 502 / upstream_error 或 upstream_auth_error | 按第 09 章处理并脱敏 |
| 请求总时限到达 | 504 / deadline_exceeded | 终止继续尝试，记录未确认的上游状态 |

以上错误码是项目目标契约，不是对 LiteLLM 原生输出的承诺；差异通过最小映射或在 V0 修改并冻结契约解决。未知等待时间不返回虚假的精确秒数。

# 09 路由规则与请求生命周期

### 9.1 选择顺序

请求鉴权与输入校验 → 解析逻辑别名 → 筛除未确认免费、无权限、隐私不符、能力不足及不可用目标 → 按人工顺序选择 → 调用 → 更新观察状态 → 正常返回或按故障规则有限备用。

V1 可将两个候选放入同一逻辑组，采用明确的部署顺序。LiteLLM 文档中的 order 数字越小优先级越高；相同顺序再由组内策略选择。[S01] 为避免混淆，界面使用“第 1 顺位 / 第 2 顺位”，不同时呈现相反方向的优先级分数。

### 9.2 首版建议策略

| 项目 | 建议默认与边界 |
| --- | --- |
| 候选数量 | general-free 首批两个已批准渠道；尽量具有独立账户额度和故障来源 |
| 质量门槛 | 人工用真实任务确认可接受；不声称自动选出“最好模型” |
| 尝试预算 | 每请求最多 2 次上游生成尝试，包含第一次；不并行竞速 |
| 层级重试 | 明确关闭消费端及底层 SDK 的额外自动重试；用模拟上游核对实际次数 |
| 多级备用 | 首版只使用一条有界候选链，不叠加多个隐式路由层 |
| 恢复 | 冷却结束后进入可尝试状态；只有成功反馈才能确认为可用 |
| 固定模型调试 | 仅管理测试流程可使用已注册部署标识，仍遵守免费和安全约束 |

### 9.3 不同故障的处理

| 故障 | 处理原则 |
| --- | --- |
| 请求格式错误、能力不支持 | 不调用或不继续备用；返回明确错误 |
| 上游 429 | 解析错误与等待信息；冷却相关部署或已确认共享的额度池；选剩余合格目标 |
| 连接失败、可重试 5xx、首事件前超时 | 在总预算内最多进行剩余尝试；超时不代表上游未执行 |
| 上游 401 / 403 | 视为凭据、授权或账户问题；停用 / 待排查，本请求默认不继续扩散 |
| 模型拒绝或安全限制 | 保留相应结果，不用换渠道规避限制 |
| 已向下游发出 SSE 事件后失败 | 终止并报告未完成；禁止透明备用 |
| 消费端取消 | 停止继续读取和尝试，尽力取消上游；不能保证上游停止计量 |

### 9.4 执行责任

路由运行时、冷却和重试由网关负责。配置发布只决定允许范围与顺序，不充当逐请求决策服务。权限和免费条件必须覆盖实际备用目标；LiteLLM 文档将备用权限与预算检查单独说明，不能假设入口检查自动覆盖备用。[S02]

# 10 免费资格、额度池与状态

### 10.1 先区分三种信息

| 信息 | 状态表达 | 对路由的影响 |
| --- | --- | --- |
| 免费资格 | 已确认免费 / 试用 / 付费 / 未知；附账户范围和复核时间 | V1 仅已确认免费可启用；其余默认排除 |
| 当前可用性 | 可尝试、冷却中、已知耗尽、上游异常、人工停用、未知 | 决定是否参与本次候选和何时再尝试 |
| 观察可信度 | 上游返回值、本地估算、未知、已过期 | 决定界面说明和保守程度；不是统一“剩余百分比” |

免费资格过期或发现政策变化后应暂停目标并复核。复核周期可以配置，但定期核查也不能保证政策在间隔内不变；供应商账户侧不产生收费的硬限制优先于网关估算。

### 10.2 额度池不是 API Key

一个部署可能同时受多个额度池约束，一个额度池也可能被多个部署共享。额度池至少标记供应商、账户 / 项目 / 组织、适用模型范围、计量维度、窗口类型与重置规则；只有官方或账户配置明确的共享范围才合并。

Gemini 文档说明按项目而非 Key 限制，日请求窗口按美国太平洋时间重置；Groq 文档说明限制在组织级应用。[S11][S12] 不能因此推断某供应商全部模型必然共用同一个计数器，仍要保存具体模型和限制维度。

### 10.3 V1 采集与恢复

优先采用已有响应头或明确的额度接口，其次记录通过本网关发出的尝试与用量，最后用 429 等错误修正可用性。Groq 的请求剩余头与 Token 剩余头分别对应不同窗口，不能混为一个余额。[S11]

本地统计仅覆盖经过本网关的流量，失败尝试是否被上游计数以供应商语义为准。未收到结果的尝试不得直接视为未消耗。V1 不承诺精确日额度预扣；多窗口原子预留和账单对账留到 V1.1。

重启优先恢复最近观察与冷却；缺失状态显示未知，禁止重置为“满额”。窗口到期仅解除可尝试限制，不宣称恢复了某个确定额度。共享范围不明时保守处理，不自动把全部模型禁用。

### 10.4 探测原则

界面刷新读取本地状态，不等于向上游发起推理。默认无周期性生成探测；冷却后允许真实请求作为受控探测，同一池只放一个探测尝试。主动“测试连接”需明确提示会消耗额度。

# 11 数据模型、配置与日志

以下是逻辑实体，不是要求新建同等数量的数据库表。能复用网关数据与配置关联就不重复存储；扩展记录使用独立命名空间，不修改上游数据库结构。

| 实体 | 必要字段 / 关系 | 建议权威位置 |
| --- | --- | --- |
| ProviderCredential | 供应商、账户范围、密钥引用、权限、免费资格证据 | 服务端秘密存储与受控配置；不保存到前端 |
| Deployment | 稳定 ID、真实模型、凭据引用、能力、QuotaPool 引用、启停状态 | 版本化配置 |
| RouteProfile | 别名、候选顺序、能力契约、隐私范围、尝试和时限规则 | 版本化配置 |
| QuotaPool | 作用范围、计量维度、窗口 / 时区、关联部署 | 与部署同版本发布的元数据 |
| QuotaObservation | pool_id、limit / remaining 可空、来源、observed_at、next_probe_at | 原生运行状态或最小持久化扩展 |
| RequestTrace | 请求 ID、调用密钥标识、别名、配置版本、开始时间、最终状态 | 原生日志优先 |
| AttemptTrace | attempt_id、request_id、序号、实际部署、耗时、上游错误、用量来源 | 原生日志或必要补充记录 |
| ConfigRevision | 版本摘要、变更说明、验证证据、生效时间、回滚目标 | 版本库与发布记录 |

### 11.1 请求与尝试必须分开计数

一个用户请求可能对应两次上游尝试。请求成功率按最终请求结果计算；上游尝试成功率按每次尝试计算；备用率统计发生第二次尝试的请求。流中断不计入完整完成率。结果质量另用任务验收集评价，不用 HTTP 200 代替。

终态建议区分：完整结束、长度截断、拒绝 / 内容限制、失败、流中断、客户端取消。另记上游执行是否未知，不能因为本地超时就断言没有消耗。

### 11.2 用量与费用

上游 Token 数据可作为有来源的观察值；本地估算附估算方法或版本。响应最终用量缺失时保留空值。界面中的“符合免费路由策略”与“供应商账单已确认零费用”是不同结论；未取得账单数据时不能显示后者。

### 11.3 保留与访问

建议仅保留 7 天必要调用元数据，默认不保存提示词、回答、工具参数或完整错误正文。密钥标识只保存可区分的非秘密 ID 或指纹。调试正文采集必须主动开启、限时、可删除，并提示隐私风险；V1 可完全不提供此功能。

所有时间以 UTC 存储；界面显示明确时区。供应商重置时区单独保存，不能用服务器本地午夜代替。导出记录默认脱敏，日志查阅通过管理权限控制。

# 12 安全、部署与非功能约束

### 12.1 建议初始运行参数

以下为本项目的建议默认值，不是厂商限额、已测性能或已经确认的用户要求。

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| 运行规模 | 单实例、明确单工作进程起步 | 进程数增加前重新验证共享状态 |
| 同时运行请求 | 2 | 包含流式请求；超出返回本地 429，不无限排队 |
| 每请求生成尝试 | 最多 2 次 | 首次与备用合计；实际网络尝试纳入追踪 |
| 请求总时限 | 90 秒 | 包含等待与流式全过程，不是每次尝试各 90 秒 |
| 首事件等待 / 流空闲 | 15 秒 / 20 秒 | 必须验证与总时限组合的实际行为 |
| 请求体大小 | 1 MiB | 仍受实际模型上下文限制 |
| 输出限制 | 默认 1024、最高 4096 Token | 目标不支持则拒绝或降低该配置的公开上限 |
| 元数据保留 | 7 天 | 默认不保存请求和回答正文 |
| 状态页面刷新 | 15 秒，仅在页面可见时 | 只读本地状态，不触发模型生成 |

### 12.2 安全基线

消费入口仅开放批准的生成与模型列表端点，管理界面、密钥管理、调试和配置接口只在私有入口开放。服务端保存供应商密钥；网页和消费应用只使用其权限范围内的调用身份。禁止客户端覆盖路由地址、凭据引用、环境文件路径或备用链。

固定镜像版本或摘要，核对签名与已披露安全问题，保留已验证回滚版本。LiteLLM 官方安全指引建议固定版本、使用受限密钥并限制网络暴露；安全公告说明仍需持续检查版本影响范围。[S08][S09]

登录、密钥轮换、备份和数据库连接使用独立凭据。备份受访问控制；不得将密钥、真实提示词、调试转储或私有数据提交到版本库。模型输出视为不可信内容，界面不直接执行或渲染未经处理的 HTML。

### 12.3 故障与隐私

数据库、权限检查或关键策略不可用时拒绝新请求，不绕过鉴权继续服务。日志存储失败应显式告警，不伪造“已留痕”。个人自用版接受维护停机，不承诺全天可用。

免费服务的数据处理条件需按账户与地区核查。Gemini 条款对部分未付费服务规定了数据改进用途和可能的人工审阅，也存在地区 / 账户例外。[S13] V1 默认只接收非敏感测试与学习内容；无法审查的隐私目标不开放。

# 13 界面信息架构与共通交互

### 13.1 六个逻辑模块

| 模块 | 核心问题 | V1 交付方式 |
| --- | --- | --- |
| UI-01 总览 | 现在能用吗？最近为什么失败？ | 复用原生统计与日志；聚合总览不足时后续补 |
| UI-02 资源池 | 有哪些合格渠道？状态和额度可信度如何？ | 原生模型信息 + 受控资源清单 + 状态日志 |
| UI-03 路由配置 | general-free 会选谁？为何排除某候选？ | 只读配置预览；修改走版本化配置流程 |
| UI-04 调用记录 | 一次请求经历了哪些尝试？ | 原生日志优先；缺失字段用最小结构化导出补 |
| UI-05 接入与设置 | 地址、密钥、版本和安全状态是什么？ | 原生密钥管理和部署信息 |
| UI-06 验证工作台 | 当前契约能否调用？错误能否被复现？ | 现成测试界面或测试工具；不做完整聊天平台 |

这些模块定义信息和任务，不强制与原生菜单逐一对应。V1 可以缺少精美聚合页面，但不能缺少安全约束、诊断证据与基本操作路径。自研 UI 统一列入 V1.1，除非 V0 证明某项必需操作没有可用替代。

### 13.2 页面组织

后续自研时采用左侧导航、顶部全局状态与版本、主区列表、右侧详情抽屉。桌面优先；窄屏详情转全屏，避免十几个字段挤在一行。表格先显示名称、状态、来源与关键动作，详细额度维度放详情页。

状态不仅依赖颜色，必须同时有文字。主要状态采用“可尝试 / 冷却中 / 已知耗尽 / 未知 / 已停用”；不可用项说明原因，不能只显示红点。键盘可操作筛选、详情与确认框；长模型名可复制并完整查看。

### 13.3 全局交互规范

请求中的按钮禁用重复提交；加载、空数据、部分失败、无权限和离线分别呈现。状态旁展示最近更新时间；过期观察不继续显示“实时”。刷新只查询网关，主动生成测试是单独按钮。

密钥默认遮罩，创建结果只在受保护场景展示；复制动作给出反馈，不写入分析日志。危险动作说明影响范围；停用最后一个候选时提示服务会不可用，但不自动添加收费候选。

配置文件模式下，模型和顺序区域为只读，并标明配置版本与修改路径。后续界面支持编辑时，必须明确区分草稿、校验通过、待发布、已生效和发布失败。

# 14 页面详设：总览与资源池

### UI-01 总览

| 区域 | 内容 / 交互 |
| --- | --- |
| 顶部状态 | 当前可用逻辑模型数、不可用原因摘要、配置版本；不承诺“服务永远在线” |
| 指标区 | 选定时间段的请求数、完整完成率、备用率、流中断数；注明统计分母 |
| 资源摘要 | 合格可尝试 / 冷却 / 耗尽 / 未知数量；点击进入相应过滤列表 |
| 最近异常 | 按时间展示错误类别、别名、请求 ID；点击打开调用详情 |
| 费用说明 | 显示“当前仅允许已确认免费渠道”；无账单数据时不显示“已节省金额” |
| 空与故障 | 无请求时提示接入测试；数据库不可读时显示获取失败，而不是零请求 |

首版原生界面没有“完整完成率”等专属口径时，先用验证过的日志查询形成报告，不替换成口径不同的成功率。聚合卡片属于后续界面增强。

### UI-02 资源池与详情

| 区域 | 内容 / 交互 |
| --- | --- |
| 列表主字段 | 部署名称、供应商、真实模型、可用性、免费资格、观察来源、更新时间 |
| 筛选与排序 | 供应商、逻辑模型、免费资格、状态；默认优先展示异常与过期待复核项 |
| 详情：资格 | 账户范围、免费依据、确认时间、复核期限、隐私范围；禁止展示完整供应商密钥 |
| 详情：额度 | 分别展示请求 / Token、分钟 / 日等窗口；显示范围、剩余、重置依据和可信度 |
| 详情：依赖 | 该部署关联的额度池、受影响的逻辑模型与备用顺序 |
| 详情：动作 | 查看最近请求、查看当前配置；主动测试需确认消耗额度 |
| 停用 / 启用 | V1 通过配置发布；后续可视化时必须显示受影响路由与生效状态 |

### 额度呈现示例

“请求窗口：上游观察值，2 分钟前更新”“Token 窗口：本地估算”“剩余额度：未知”“下次可尝试时间：依据 Retry-After 推算”。这些是文案示例，不代表当前存在真实监控数据。

没有同口径上限时不画百分比进度条。日请求与分钟 Token 不合并成一个“总余额”。多个部署共享同一池时明确标识“共享”，避免用户把展示值相加。

### 不支持的操作

不提供“忽略免费限制继续调用”“强制恢复全部额度”或批量生成探测。人工恢复只表示允许重新尝试，不能修改供应商实际额度。

### 时间线文案示例

“第 1 次：渠道 A 返回限流，进入冷却；第 2 次：渠道 B 完整结束。”或者“第 1 次：已经输出，随后连接中断；未执行备用。”示例仅用于说明界面要求。

### UI-06 验证工作台

| 区域 | 内容 / 交互 |

### 界面范围控制

V1 不做会话搜索、文件库、模型对比对话、多分支消息、分享链接和 Agent 任务列表。测试台的目标是验证契约和排查问题，不是复制成熟聊天产品。

# 17 关键操作流程与异常文案

### 17.1 核心流程

| 流程 | 步骤与关键确认 |
| --- | --- |
| 首次接入 | 确认消费协议 → 核查账户免费 / 隐私条件 → 添加凭据引用与部署 → 校验配置 → 测试单目标 → 测试备用 → 发布 → 创建受限密钥 |
| 调整顺序 | 修改配置草稿 → 查看候选能力与资格差异 → 模拟主渠道失败 → 维护窗口发布 → 核对生效版本 → 保留回滚 |
| 免费池全部不可用 | 返回 no_eligible_free_model → 查看各候选排除原因 → 有可信时间则提示可再尝试 → 未知则提示稍后检查，不自动付费 |
| 流式中断 | 保留已交付内容 → 标记未完成 → 禁止透明备用 → 用户选择显式重新生成；新请求重新计入次数 |
| 密钥轮换 | 创建新受限密钥 → 消费端切换并验证 → 撤销旧密钥 → 测试旧密钥被拒绝 → 记录操作时间 |
| 升级失败 | 停止继续发布 → 保留故障证据 → 按备份与迁移兼容性恢复 → 运行最小验收 → 恢复流量 |

### 17.2 统一文案

| 状态 | 建议文案 | 禁止表达 |
| --- | --- | --- |
| 额度未知 | “该渠道未提供可用的余额数据；当前状态来自最近调用。” | “剩余 100%”或“剩余 0” |
| 冷却 | “已触发限制，下次可尝试时间依据上游反馈推算。” | “到点保证恢复满额” |
| 全部不可用 | “当前没有满足要求的免费渠道，本次未转入收费调用。” | “已自动升级到付费保障服务” |
| 流中断 | “回答未完成。已保留收到的内容，未自动切换模型。” | “回答完成” |
| 配置待生效 | “变更已保存为草稿；当前仍运行版本 X。” | 只显示“保存成功” |
| 元数据缺失 | “未取得最终用量，上游实际消耗未知。” | “本次未消耗任何额度” |
| 免费资格未确认 | “该渠道尚未完成资格核查，不能启用。” | “模型名称包含 free，因此一定免费” |

### 17.3 时间与刷新

所有倒计时注明来源，时间显示时区。页面从后台恢复时先刷新本地状态再允许依赖状态的操作；不能拿几分钟前的预览作为此刻保证。断网时保留旧值但标记过期，不能把请求失败的空结果渲染成零资源。

### 17.4 操作影响范围

停用共享池或部署时展示受影响别名。已有流是否继续以该操作的发布规则为准；V1 使用维护窗口，不能让一次请求中途换配置。紧急撤销与停用的生效时点必须在实际版本上测试并记录。

### 18.2 三个阶段的交付门槛

V0 结束：证明目标契约和关键约束能够落地，并形成“原生满足 / 需要薄扩展 / 暂不支持”的差异表。不能把成功调用一次当作完成 V0。

V1 结束：第 19–20 章适用测试全部通过，至少一个真实消费端完成联调，账户免费资格和供应链核查有记录。任何收费越界、权限越界、密钥泄露或流中断被伪装成成功的问题都阻塞发布。

V1.1 启动：先收集实际使用缺口。只有“现成后台无法完成高频操作”“明确需要工具或结构化输出”“出现多进程状态问题”等证据，才启动对应扩展，不按大平台清单一次铺开。

### 18.3 自研界面的启动条件

若只是界面不够好看，先不开发。若缺失字段影响排障但日志可读，先补查询；若频繁手工配置造成真实错误，再建设可视化草稿、校验和发布流程。技术选型优先复用熟悉的前端栈，独立 Spring Boot 管理服务需另写收益和依赖说明。

# 19 验收测试：协议与调度

**当前状态：以下均为待执行测试，不是已经通过的结果。**模拟上游测试与真实账户测试分开记录；模拟成功不能代替账户免费资格核查。

| 编号 | 场景与操作 | 必须观察到的结果 |
| --- | --- | --- |
| AT-01 | 调用两个公开端点；请求未知别名与非开放端点 | 正常协议可解析；未知别名不走默认；不暴露管理端点 |
| AT-02 | 首真实消费端完成非流式、流式和一次错误处理 | 无需适配供应商格式；客户端默认参数和重试行为已记录 |
| AT-03 | 两候选都健康；再使第一候选不可用 | 首先选第 1 顺位；不可用后才用第 2；可查实际模型 |
| AT-04 | 返回分片文本、空内容块和可选最终用量块 | 文本无重复或丢失；ID 和结束标志可解析；正常与未知用量区分 |
| AT-05 | 分别在首事件前、角色事件后、正文输出后断流 | 仅首事件前允许有界备用；之后保持未完成，不拼接和伪成功 |
| AT-06 | 发送不支持角色、工具、结构化格式、关键参数及超限 n | 明确 400；不靠删除参数完成请求；主目标与备用均适用 |
| AT-07 | 模拟收费或免费资格未知目标进入主链 / 备用链 | 被禁止目标的上游调用数为零；不存在收费兜底 |
| AT-08 | 全部目标无资格或不可用；另测模型拒绝与长度截断 | 无目标时 503；拒绝和截断保留语义，不被计作完整回答 |
| AT-09 | 不返回 usage；返回可区分的估算；观察值过期 | 用量和余额显示未知 / 估算 / 过期，不自动归零或满额 |
| AT-10 | 多轮历史切换渠道；再发送过长上下文 | 顺序和关键内容保持；网关不依赖隐藏会话，不静默裁剪 |
| AT-11 | 第一渠道返回 429、可信等待时间或共享池限流 | 有界备用；冷却只影响确认相关的范围；恢复后受控尝试 |
| AT-12 | 叠加客户端 / SDK 重试、5xx 和长等待 | 实际上游生成尝试不超过 2；总时限内停止继续尝试 |

### 19.1 测试数据要求

使用固定的非敏感样例与可控模拟服务器。模拟器应能够输出延迟首事件、半途断流、不同窗口的限流头、缺失用量和错误状态；仅依靠真实免费渠道很难稳定复现边界，也会消耗额度。

### 19.2 结果记录

每项保留网关版本、配置版本、消费端版本、操作步骤、预期与实际结果、请求 ID、脱敏日志和结论。失败项必须能重现，不能只截图“看起来成功”。

模型输出本身可能变化；文本质量不做逐字快照比对。自动验收聚焦契约、权限与终态；内容质量通过另行定义的任务完成标准评价。

| AT-17 | 创建、轮换、撤销消费密钥；从消费入口访问管理功能 | 新密钥可用、旧密钥被拒绝；权限与生效时点明确 |
| AT-18 | 一请求触发两次尝试，分别成功、中断或失败 | 同一请求可关联所有尝试、配置版本和终态；无密钥 / 正文泄露 |
| AT-19 | 检查日志、异常、导出、备份和保留期清理 | 无默认正文采集；过期数据按策略删除；清理失败有告警 |
| AT-20 | 发布无效配置、制造数据库同名覆盖、执行回滚 | 拒绝或发现冲突；失败不显示已生效；恢复后版本可验证 |
| AT-21 | 备份恢复、网关升级、数据库迁移失败和数据库中断 | 可按手册恢复；故障时不绕过权限；不假设跨版本数据库兼容 |
| AT-22 | 消费端主动取消或读取极慢后断开 | 停止新尝试、释放本地并发资源；不声称上游必已取消计量 |
| AT-23 | 同时发起超过建议并发的请求；冷却后并发探测 | 超额有界拒绝；状态更新不明显丢失；同池不形成探测风暴 |
| AT-24 | 用不符合隐私范围的配置请求、伪造客户端覆盖参数 | 不转发给未批准渠道；未做内容识别时不宣称自动检测了敏感信息 |

### 20.1 发布阻塞项

收费或未授权目标被调用、供应商密钥泄露、绕过服务端地址限制、流已交付后偷偷切换、错误结束被标记为成功、请求无限重试、配置失效却显示已发布，任何一项出现都不能发布 V1。

### 20.2 使用效果验证

建议准备 20 个个人真实任务，覆盖普通问答、代码解释和文本改写。比较固定主模型与有界备用方案的任务完成率、等待时间和维护负担。任务数量是建议值，不是统计显著性承诺。

如果备用并未改善实际可用性，或运维时间明显高于收益，可以退回单一主渠道加手动备用。项目目标是减少使用成本，不是证明复杂路由一定有价值。

### 21.2 风险登记

| 风险 | 控制方式 |

### 21.3 何时扩展

出现新的真实消费端且要求工具、结构化输出或其他协议时，建立独立能力配置，并测试所有备用目标。出现多进程或服务重启造成无法接受的状态偏差时，再引入共享存储和原子预扣。现成后台不能解决高频操作时，再开发 Next.js 控制台；只有管理业务确需独立后端时才评估 Spring Boot。

**不变的方向：先把可用范围说清楚，再扩大范围。统一接口要稳定，内部实现可以替换，但任何替换都必须重新通过契约与故障测试。**

# 附录 A 术语与开发交付物

### A.1 术语

| 术语 | 本文含义 |
| --- | --- |
| Provider / 供应商 | 提供实际模型 API 的服务方；不等于具体模型 |
| Deployment / 部署渠道 | 某凭据、某端点与某真实模型组成的一条可调用路径 |
| RouteProfile / 路由配置 | 消费端使用的逻辑别名及其候选、能力和安全约束 |
| QuotaPool / 额度池 | 在某作用范围和时间窗口内共享的计量限制；不等于一把 Key |
| Fallback / 备用切换 | 在允许的故障、资格和预算范围内改用另一候选 |
| Cooldown / 冷却 | 临时不参与调用，等待可再次尝试；不是已恢复证明 |
| Request / Attempt | 一次消费请求 / 一次实际上游尝试，两者分别计数 |
| RPM、RPD、TPM、TPD | 每分钟 / 每日请求数与 Token 数；不同维度不可直接相加 |
| 契约测试 | 验证输入、输出、错误和流式行为满足消费端约定 |

### A.2 建议仓库交付物

| 目录或文件 | 内容 |
| --- | --- |
| docs/ | 本文、能力矩阵、协议范围、运维手册与决策记录 |
| config/ | 无明文密钥的网关配置与同版本路由元数据 |
| deploy/ | 固定版本的单机部署声明、入口规则与环境变量说明 |
| tests/contract/ | 文本、流式、字段与错误映射测试 |
| tests/faults/ | 限流、超时、中断、取消和备用路径测试 |
| tests/security/ | 权限、路由覆盖、密钥、隐私范围与日志脱敏测试 |
| extensions/ | 仅保存通过缺口评审的最小插件；没有需求可为空 |
| evidence/ | 脱敏测试报告、开源功能差异表、镜像 / 配置版本记录 |
| ops/ | 备份、恢复、发布、回滚和异常排查说明 |

### A.3 开发启动清单

先建立能力矩阵与测试占位，不先画完整平台。确认首消费端后冻结输入、正常响应、错误及流终止行为；确认账户后登记可用模型与免费依据；确认网关版本后对照测试清单执行。通过后再将本稿升级为 v1.0 开发基线，并记录相对 v0.1 的变更。

本次交付为开发准备文档，不包含可运行服务、已注册账户、真实密钥、数据库建表脚本、可点击原型或已通过的测试报告。
